# 星月五子棋逻辑与 AI 难度说明

本文档描述当前项目中“星月五子棋”的实际实现，以代码为唯一依据。规则实现位于 `src/games/gomokuEngine.js`，AI 实现位于 `src/games/gomokuAI.js`，异步计算入口位于 `src/games/gomoku.worker.js`，界面调用位于 `src/components/BoardGame.vue`。

## 1. 游戏规则

### 1.1 基础规则

| 项目 | 当前实现 |
| --- | --- |
| 棋盘 | 15 × 15，共 225 个交叉点 |
| 玩家棋子 | `human`，界面显示为黑棋 |
| 哥伦比娅棋子 | `ai`，界面显示为白棋 |
| 先手 | 开局时可选择玩家先手或哥伦比娅先手 |
| 落子 | 双方轮流在空位落一枚棋子，棋子不会移动或消失 |
| 获胜 | 横、竖、左斜、右斜任一方向形成连续至少 5 子 |
| 长连 | 6 子或更多连续棋子同样判胜，不要求“恰好五子” |
| 平局 | 没有胜者且 225 个位置全部落满 |
| 禁手 | 没有三三、四四、长连等禁手规则 |

因此，当前玩法属于无禁手的自由五子棋，不是带黑方禁手的竞技连珠规则。

### 1.2 状态结构

每一局使用以下状态：

| 字段 | 含义 |
| --- | --- |
| `board` | 15 × 15 二维数组；空位为 `null`，棋子为 `human` 或 `ai` |
| `moves` | 按顺序保存全部落子记录 |
| `currentPlayer` | 当前应落子的玩家 |
| `moveCount` | 已落子数量 |
| `status` | `playing`、`won`、`lost` 或 `draw` |
| `winner` | 胜者；未结束时为 `null` |
| `winningLine` | 获胜方向上的完整连续棋子坐标，可能超过 5 个 |

落子采用不可变更新：复制棋盘行，生成新状态，不直接修改旧状态。越界、已有棋子或对局已结束时，落子请求会被忽略并返回原状态。

### 1.3 胜负判定

每次有效落子后，只从最后落子位置检查以下四个方向：

```text
横向  (0, 1)
纵向  (1, 0)
主对角线  (1, 1)
副对角线  (1, -1)
```

对每个方向同时向正、反两端收集同色连续棋子。包含最后落子的整条连续线长度达到 5 即获胜。若无人获胜且棋盘已满，则判平局；否则切换当前玩家。

## 2. 一次完整回合的执行流程

1. 玩家点击棋盘空位。
2. 界面检查：AI 未在思考、对局未结束、当前确实轮到玩家、目标位置为空。
3. 规则引擎落子并立即检查玩家是否获胜或棋盘是否已满。
4. 若对局继续，等待 180 ms 后请求 AI 落子。
5. 当前状态通过 JSON 深复制后发送给短生命周期 Web Worker。
6. Worker 执行 `chooseGomokuMove`，返回 AI 选择的坐标。
7. 主线程再次通过规则引擎落子并检查 AI 是否获胜。

若选择哥伦比娅先手，重新开局后等待 120 ms 请求第一步 AI 落子。重新开始或离开页面时会中止当前请求并终止 Worker；若浏览器不支持 Worker 或 Worker 出错，则回退到异步主线程计算。

## 3. AI 总体决策顺序

三个难度都遵循同一套最高优先级战术规则：

1. 生成并排序候选位置。
2. 如果 AI 当前存在一步成五的位置，立即获胜。
3. 否则，如果玩家当前存在一步成五的位置，立即堵住。
4. 如果 AI 能由活三延伸出活四，优先形成自己的活四。
5. 如果玩家能由活三延伸出活四，立即占据其延伸点进行堵截。
6. 否则，再按所选难度执行随机选择或极小化极大搜索。

也就是说，即使是简单难度，也不会故意放弃已经看到的一步必胜点，并会优先阻挡已经看到的玩家一步必胜点。如果 AI 和玩家同时存在一步成五，AI 优先完成自己的胜利。

## 4. 候选位置生成与排序权重

### 4.1 候选位置范围

AI 不会遍历所有空位。它只收集任意已有棋子周围切比雪夫距离不超过 2 的空位，即以每枚棋子为中心的 5 × 5 区域。

```text
|行差| ≤ 2 且 |列差| ≤ 2
```

候选位置用集合去重。空棋盘是特例，只返回中心点 `(7, 7)`。

### 4.2 候选排序公式

普通候选位置的排序分为：

```text
候选优先级 = 中心分 + 周围己方棋子分 + 周围对手棋子分 + 直接堵胜分
```

排序函数支持传入视角。根节点按 AI 视角排序；极小化极大搜索的 AI 节点按 AI 视角排序，玩家节点按玩家视角排序。若该位置能让当前节点一方立即成五，则不再使用上述加法，直接返回 `10,000,000`。

#### 中心分

```text
12 - |7 - row| - |7 - col|
```

棋盘正中心为 12，四角为 -2。

#### 5 × 5 邻域权重

遍历候选位置周围行差、列差均不超过 2 的已有棋子，不包括候选位置本身：

| 周围棋子 | 曼哈顿距离 | 每枚增加值 |
| --- | ---: | ---: |
| 当前节点一方的棋子 | ≤ 1 | +9 |
| 当前节点一方的棋子 | > 1 | +3 |
| 对手棋子 | ≤ 1 | +8 |
| 对手棋子 | > 1 | +2 |

这里的“距离 ≤ 1”只包括上下左右紧邻位置；斜对角的曼哈顿距离为 2，使用较远权重。

#### 直接战术权重

| 情况 | 排序分 |
| --- | ---: |
| 当前节点一方落在这里立即成五 | 10,000,000，直接作为总优先级 |
| 对手落在这里会立即成五 | +10,000 |

排序仅用于决定哪些候选进入后续随机池或搜索树，不等于最终局面评分。排序相同则保留候选集合原有顺序。

一步成五、一步堵胜和活三检测都会在未做难度截断的完整邻近候选集合中执行，避免高优先级威胁因根候选数量限制而漏检。

## 5. 共用棋型评分权重

简单、中等、困难共用同一套棋型数值。设 `S(P)` 为某一方所有棋型与位置分之和，则从指定视角进行的局面评分为：

```text
局面评分 = S(己方) - S(对方)
```

攻防基础权重是 1:1，没有按难度给进攻或防守额外乘数。

### 5.1 连续棋型分值

“开放端数量”指连续棋子两端仍为空位的数量。

| 连续棋型 | 开放端 | 分值 |
| --- | ---: | ---: |
| 五连 | 任意 | 1,000,000 |
| 超过五连 | 任意 | 1,000,000 + `(长度 - 5) × 1,000` |
| 活四 | 2 | 100,000 |
| 冲四 | 1 | 10,000 |
| 死四 | 0 | 0 |
| 活三 | 2 | 5,000 |
| 眠三 | 1 | 500 |
| 死三 | 0 | 0 |
| 活二 | 2 | 200 |
| 眠二 | 1 | 20 |
| 死二 | 0 | 0 |
| 单子 | 任意 | 0 |

### 5.2 窗口棋型附加分

连续段计分后，算法还会把每一条线转换为字符串并扫描窗口：

```text
1 = 当前被评分方的棋子
0 = 空位
2 = 对手棋子
```

| 模式 | 附加分 |
| --- | ---: |
| `011110` | 100,000 |
| `01110` | 5,000 |
| `01101` | 500 |
| `01011` | 500 |
| `10110` | 500 |
| `11010` | 500 |
| `01100` | 200 |
| `00110` | 200 |
| `01010` | 200 |

窗口允许重叠匹配。连续棋型分和窗口附加分会同时累计，例如标准 `011110` 活四会获得连续活四分，再获得一次窗口附加分。棋盘边缘不会自动补成 `0`，对手棋子 `2` 也会阻断匹配。

### 5.3 棋子位置分

每一枚棋子还会获得中心位置分：

```text
max(0, 8 - |7 - row|) + max(0, 8 - |7 - col|)
```

| 位置 | 分值 |
| --- | ---: |
| 正中心 `(7, 7)` | 16 |
| 四角 | 2 |
| 其他位置 | 2 到 16 之间 |

这个分值远小于成型棋型，主要用于开局走向和同类局面的细微区分。

## 6. 极小化极大搜索

中等和困难使用带 Alpha-Beta 剪枝的极小化极大搜索：

- AI 节点取最大值。
- 玩家节点取最小值。
- 搜索到设定深度后使用共用棋型评分函数。
- 每个节点先按轮到落子的一方进行候选排序并截断，以便优先展开该方最有战术价值的回复。
- 若最后一步已经成五，立即返回终局分，不再继续展开。

终局基础分为：

```text
WIN_SCORE = 1,000,000 × 10 = 10,000,000
```

| 搜索结果 | 返回值 |
| --- | --- |
| 根搜索方获胜 | `10,000,000 + 当前剩余深度` |
| 根搜索方失败 | `-10,000,000 - 当前剩余深度` |

剩余深度修正会让 AI 在多条获胜路线中偏向更快获胜，并在无法避免失败时偏向延后失败。

根节点出现相同最终分时，选择线性坐标 `row × 15 + col` 更小的位置，即更靠前的行、再更靠前的列。中等和困难因此是确定性的；简单难度除外。

## 7. 三个难度的具体算法

界面文案与内部难度值的映射为：

| 界面选项 | 内部值 |
| --- | --- |
| 多让一点 | `easy` |
| 稍微让让 | `medium`，默认值 |
| 不用让 | `hard` |

### 7.1 参数总表

| 参数 | 简单：多让一点 | 中等：稍微让让 | 困难：不用让 |
| --- | ---: | ---: | ---: |
| 初始候选截断数量 | 48 | 48 | 36 |
| 一步必胜检查 | 是 | 是 | 是 |
| 一步堵胜检查 | 是 | 是 | 是 |
| 活三延伸/堵截硬规则 | 是 | 是 | 是 |
| 根候选池 | 排序前 7 个 | 排序前 16 个 | 排序前 12 个 |
| 根候选选择方式 | 等概率随机 | 取搜索最高分 | 取搜索最高分 |
| 传入搜索的深度 | 无 | 1 | 2 |
| 实际向前考虑的半回合数，包含本次 AI 落子 | 1 | 2 | 3 |
| 搜索树第一层分支上限 | 无 | 玩家回复 12 个 | 玩家回复 8 个 |
| 搜索树第二层分支上限 | 无 | 无 | AI 再回复 12 个 |
| 同分处理 | 随机池内等概率 | 取较小线性坐标 | 取较小线性坐标 |

困难难度的初始候选数和根候选数反而比中等少，是为了把计算预算用于更深的搜索；候选已经先按战术优先级排序，因此保留的是更高优先级部分。

### 7.2 简单难度

在完成“一步取胜”“一步堵胜”和“活三延伸/堵截”后：

1. 取排序后的前 7 个候选；不足 7 个则全部保留。
2. 对候选不再进行局面评分或极小化极大搜索。
3. 每个候选以 `1 / 候选数` 的相同概率被选中。

简单难度实际使用的是候选排序权重，但最终在前 7 名内加入均匀随机噪声。因此它通常会在棋子附近行动，却可能错过更长远的攻防路线。

### 7.3 中等难度

在完成“一步取胜”“一步堵胜”和“活三延伸/堵截”后：

1. 取排序后的前 16 个根候选。
2. 依次假设 AI 在每个候选处落子。
3. 搜索玩家接下来最有利的一步；玩家回复按玩家视角排序后截取最多 12 个，再由最小化节点选择其中评分最低的一步。
4. 对“AI 本次落子 + 玩家一次回复”后的棋盘进行共用棋型评分。
5. 选择玩家最佳反击之后，AI 仍能得到最高最低保障分的走法。

因此代码中的 `depth = 1` 不代表只看 AI 当前一步；根落子在进入搜索前已经完成，实际包含玩家的一步回复，共向前考虑 2 个半回合。

### 7.4 困难难度

在完成“一步取胜”和“一步堵胜”后：

1. 与其他难度一样，先检测 AI 是否可以把自己的活三延伸为两端开放的连续活四；若可以，直接走该点形成强制进攻。
2. 与其他难度一样，检测玩家是否可以把活三延伸为两端开放的连续活四；若可以，AI 立即占据延伸点。存在多个点时，优先选择能消除更多后续活四入口的位置，再比较完整局面分。
3. 没有上述强制威胁时，取排序后的前 12 个根候选。
4. 依次假设 AI 在每个候选处落子。
5. 第一搜索层考虑玩家回复，按玩家视角排序并最多展开 8 个候选。
6. 第二搜索层考虑 AI 再回复，按 AI 视角排序并最多展开 12 个候选。
7. 对“AI 本次落子 + 玩家回复 + AI 再回复”后的棋盘进行共用棋型评分。
8. 使用 Alpha-Beta 剪枝减少无需继续计算的分支。

代码中的 `depth = 2` 对应根落子之后再搜索两层，实际共向前考虑 3 个半回合。

## 8. 权重之间的优先级关系

关键数值从高到低如下：

| 层级 | 数值或方式 | 作用 |
| --- | ---: | --- |
| 搜索终局 | 约 ±10,000,000 | 压倒任何普通局面评分 |
| 五连棋型 | 1,000,000 | 已形成五连的静态评分 |
| 活四 | 100,000，另可能叠加同值窗口分 | 强制性极高的威胁 |
| 冲四 | 10,000 | 单端可延伸四连 |
| 活三 | 5,000，另可能叠加同值窗口分 | 双端可延伸三连 |
| 眠三/断三 | 500 | 次级威胁 |
| 活二/部分断二 | 200 | 发展潜力 |
| 眠二 | 20 | 较弱连接 |
| 中心位置 | 每子 2 到 16 | 轻微位置偏好与破同分 |

候选排序中的 `10,000,000`、`10,000` 和邻域分只控制搜索顺序及入选范围；真正比较中等、困难根走法时，以终局分或完整棋型局面分为准。

## 9. 当前未参与决策的预留权重

`gomokuAI.js` 中存在一个 `moveHeuristic` 函数，但当前没有任何调用点，不会影响任一难度的实际落子。该函数保留的计算方式为：

```text
假设落子后的己方视角局面分
+ 若该点能阻止对手一步成五则加 800,000
+ 12 - |7 - row| - |7 - col|
```

若当前搜索方可直接成五，则它会返回 `10,000,000`。除非未来代码显式调用该函数，否则上述 `800,000` 防守权重只是预留实现，不应当视为当前 AI 的生效参数。

## 10. 当前自动化测试覆盖

现有五子棋测试覆盖：

- 横、竖、两种斜线方向的五连；
- 棋盘边缘和角落的五连；
- 六连判胜、四连不判胜；
- 落子不会修改旧状态；
- AI 有一步必胜时立即获胜；
- 玩家有一步必胜时立即阻挡；
- 三个难度都会堵截玩家活三；困难难度另覆盖横、竖和两种斜线方向的回归用例；
- 活三、活二、四连之间的评分高低关系。

目前尚未为每一种窗口棋型、每个难度的分支上限、随机候选分布和 Alpha-Beta 剪枝路径分别建立独立测试。
